# PDF Orientation Normalizer

Микросервис для автоматического определения и исправления ориентации страниц в PDF-документах. Разработан мной в рамках тестового задания.

## Стек технологий

В проекте использовал следующий стек:
* **Python 3.10+** — основной язык разработки.
* **FastAPI** — фреймворк для создания REST API.
  * *Почему:* Высокая производительность (асинхронность), встроенная валидация данных (Pydantic) и автоматическая генерация документации (Swagger UI).
* **PyMuPDF (fitz)** — библиотека для работы с PDF.
  * *Почему:* Позволяет извлекать страницы как изображения и изменять угол поворота путем редактирования метаданных (`rotation`). Это сохраняет исходное качество документа, текстовый слой и цифровые подписи (ЭЦП).
* **Tesseract OCR (pytesseract)** — движок оптического распознавания.
  * *Почему:* Имеет встроенный механизм OSD (Orientation and Script Detection) и отлично читает кириллицу. Открытое решение, не требующее внешних API.
* **Pillow (PIL)** — библиотека для обработки изображений.
  * *Почему:* Необходима для очистки "грязных" сканов, удаления водяных знаков и синих печатей перед передачей изображения в нейросеть.
* **Docker** — для контейнеризации и удобного развертывания.

### Альтернативы, которые рассматривались
1. **Тяжелые ML-модели (YOLO, кастомные сверточные сети)**
   * *Почему отказался:* Избыточно для задачи поиска ориентации текста. Требует установки тяжелых зависимостей, потребляет много оперативной памяти и увеличивает вес Docker-образа в несколько раз.
2. **Конвертация PDF в картинки и обратно (pdf2image + Pillow)**
   * *Почему отказался:* Если растрировать PDF, повернуть картинку и снова собрать PDF, документ полностью теряет текстовый слой (становится невыделяемым) и оригинальное качество, а размер файла многократно возрастает.
3. **Библиотеки PyPDF2 / pdfrw**
   * *Почему отказался:* Они умеют поворачивать страницы (редактировать метаданные), но не умеют рендерить страницы в изображения, что критически необходимо для передачи картинки в анализатор Tesseract. PyMuPDF закрывает обе потребности.

## Как работает алгоритм (Двухступенчатая архитектура)

Для работы со сложными сканами реализовал алгоритм **Fast Path + OCR Fallback**:

1. **Прием и изоляция:** Сервис принимает файл (`application/pdf`) в оперативную память (`io.BytesIO`). Временные файлы на диск не сохраняются ради скорости и безопасности.
2. **Рендеринг и Предобработка:** Документ разбивается на страницы. Каждая страница рендерится в изображение (300 DPI). Далее применяется фильтр через Pillow: перевод в градации серого, повышение резкости краев букв и мягкая бинаризация. Это убивает фоновый шум, бледные водяные знаки и цветные печати, оставляя только контрастный текст.
3. **Шаг 1: Быстрый метод (OSD):** Изображение передается в Tesseract OSD. Если уверенность нейросети высока (`confidence > 15.0`), мы применяем предложенный угол.
4. **Шаг 2: Запасной метод (OCR Fallback):** Если OSD дает сбой (например, путает линии таблиц с направлением текста, или скан сделан с сильным перекосом), запускается запасной план. Алгоритм поворачивает изображение на 0, 90, 180 и 270 градусов, пытается распознать текст (`--psm 6`) и считает количество кириллических символов (`[а-яА-ЯёЁ]`). Угол, при котором найдено больше всего осмысленных букв (и их больше 20), признается верным.
5. **Сохранение и возврат:** Измененные метаданные применяются к PDF-объекту в памяти, после чего бинарный поток возвращается клиенту.

## Инструкция по запуску

### Вариант 1: Запуск через Docker
Для запуска потребуется только установленный и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Соберите Docker-образ (находясь в корне проекта):
   ```bash
   docker build -t pdf-orient-service .
   ```
2. Запустите контейнер:
   ```bash
   docker run -p 8000:8000 pdf-orient-service
   ```
*Сервис будет доступен по адресу `http://127.0.0.1:8000`*

### Вариант 2: Локальный запуск на Windows
1. Установите **Tesseract OCR**:
   * Скачайте установщик [UB-Mannheim Tesseract](https://github.com/UB-Mannheim/tesseract/wiki).
   * Установите программу (по умолчанию в `C:\Program Files\Tesseract-OCR`).
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите веб-сервер:
   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

## Использование API
После запуска сервиса интерактивная документация Swagger UI будет доступна по адресу:  
**http://127.0.0.1:8000/docs**

Для тестирования разверните метод `/api/v1/orient`, нажмите **Try it out**, загрузите тестовый PDF-файл и нажмите **Execute**. Нормализованный файл можно будет скачать из блока ответа. Сервер также выводит подробные логи процесса нормализации в терминал.

## Результаты тестирования

Я провел тестирование сервиса на сложных краевых сценариях, чтобы убедиться в его отказоустойчивости:

* **Сценарий 1: Корректный документ.** PDF-файл, в котором все страницы изначально имеют правильную ориентацию.
  * *Итог:* Успешно. Алгоритм OSD быстро определяет угол как 0 и оставляет страницы без изменений.
* **Сценарий 2: Документ со смешанной ориентацией.** PDF-файл, страницы которого повернуты вразнобой (на 90, 180 и 270 градусов).
  * *Итог:* Успешно. Каждая страница анализируется независимо и приводится к единой ориентации.
* **Сценарий 3: Сложные сканы (выписки из ЕГРН, таблицы, печати, перекос).** Документы с графическим мусором, где сетка таблиц сбивает классический поиск базовых линий.
  * *Итог:* Успешно. Алгоритм OSD отсекает такие страницы по низкому порогу уверенности (`< 15.0`). Далее управление берет на себя метод `OCR Fallback`, который физически читает текст под разными углами и со 100% точностью восстанавливает правильное положение листа на основе количества кириллических символов.
* **Сценарий 4: Поврежденный или не-PDF файл.** Попытка загрузить переименованный текстовый файл (`.txt` -> `.pdf`).
  * *Итог:* Успешно. Сервис корректно отлавливает проблему на этапе валидации (отсутствие `%PDF-`) и возвращает контролируемую ошибку 400.
