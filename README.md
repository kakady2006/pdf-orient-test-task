# PDF Orientation Normalizer

Микросервис для автоматического определения и исправления ориентации страниц в PDF-документах. Разработан мной в рамках тестового задания.

## Стек технологий

В проекте использовал следующий стек:
* **Python 3.10+** — основной язык разработки.
* **FastAPI** — фреймворк для создания REST API.
  * *Почему:* Высокая производительность (асинхронность), встроенная валидация данных (Pydantic) и автоматическая генерация документации (Swagger UI), что идеально подходит для микросервисной архитектуры.
* **PyMuPDF** — библиотека для работы с PDF.
  * *Почему:* Позволяет извлекать страницы как изображения для анализа и, самое главное, изменять угол поворота страницы путем редактирования метаданных (свойства `rotation`). Это сохраняет исходное качество документа, текстовый слой и цифровые подписи (ЭЦП).
* **Tesseract OCR** — движок оптического распознавания.
  * *Почему:* Имеет встроенный надежный механизм OSD (Orientation and Script Detection). Это бесплатное, open-source решение, не требующее подключения к внешним платным API.
* **Docker** — для контейнеризации и удобного развертывания.

### Альтернативы, которые рассматривались
1. **Тяжелые ML-модели (YOLO, кастомные сверточные сети)**
   * *Почему отказался:* Избыточно для задачи поиска ориентации текста. Требует установки тяжелых зависимостей, потребляет много оперативной памяти и увеличивает вес Docker-образа в несколько раз.
2. **Конвертация PDF в картинки и обратно (pdf2image + Pillow)**
   * *Почему отказался:* Если растрировать PDF, повернуть картинку и снова собрать PDF, документ полностью теряет текстовый слой (становится невыделяемым) и оригинальное качество, а размер файла многократно возрастает.
3. **Библиотеки PyPDF2 / pdfrw**
   * *Почему отказался:* Они умеют поворачивать страницы (редактировать метаданные), но не умеют рендерить страницы в изображения, что критически необходимо для передачи картинки в анализатор Tesseract. PyMuPDF закрывает обе потребности.

## Как работает алгоритм
1. **Прием и валидация:** Сервис принимает файл через `POST`-запрос. Проверяется MIME-тип (`application/pdf`) и наличие сигнатуры `%PDF-` в начале файла. При несовпадении возвращается ошибка `422` или `400`.
2. **Изоляция:** Документ загружается в оперативную память (`io.BytesIO`). Сохранение временных файлов на жесткий диск не используется для повышения скорости и безопасности.
3. **Постраничный рендеринг:** Документ разбивается на страницы. Каждая страница конвертируется в растровое изображение с разрешением 300 DPI (оптимально для OCR).
4. **Анализ (OSD):** Изображение передается в Tesseract, который возвращает угол, на который нужно довернуть текст (`Rotate`), и уровень уверенности нейросети (`Orientation confidence`).
5. **Применение эвристики:** 
   * Если уверенность Tesseract выше порога (`> 0.5`) и угол поворота отличен от нуля, вычисляется новый абсолютный угол страницы с учетом ее текущего состояния `(current_rotation + angle) % 360`.
   * Страницы без читаемого текста (схемы, пустые листы) или с низкой уверенностью пропускаются.
6. **Сохранение и возврат:** Измененные метаданные применяются к PDF-объекту в памяти, после чего бинарный поток байтов возвращается клиенту с заголовком `application/pdf`.

## Инструкция по запуску

### Вариант 1: Запуск через Docker 
Для запуска потребуется только установленный и запущенный [Docker Desktop](https://www.docker.com/products/docker-desktop/).

1. Соберите Docker-образ (находясь в корне проекта):
   ```bash
   docker build -t pdf-orient-service .
   ```
2. Запустите контейнер:
   ```bash
   docker run -p 8000:8000 pdf-orient-service
   ```
*Сервис будет доступен по адресу `http://127.0.0.1:8000`*

### Вариант 2: Локальный запуск на Windows
1. Установите **Tesseract OCR**:
   * Скачайте установщик [UB-Mannheim Tesseract](https://github.com/UB-Mannheim/tesseract/wiki).
   * Установите программу (по умолчанию в `C:\Program Files\Tesseract-OCR`).
   * **Важно:** Добавьте путь к папке Tesseract в системную переменную `PATH` или укажите прямой путь в коде (`processor.py`):
     `pytesseract.pytesseract.tesseract_cmd = r'C:\Program Files\Tesseract-OCR\tesseract.exe'`
2. Создайте и активируйте виртуальное окружение:
   ```bash
   python -m venv .venv
   .venv\Scripts\activate
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Запустите веб-сервер:
   ```bash
   uvicorn main:app --host 0.0.0.0 --port 8000 --reload
   ```

## Использование API
После запуска сервиса (любым из способов) интерактивная документация Swagger UI будет доступна по адресу:  
**http://127.0.0.1:8000/docs**

Для тестирования разверните метод `/api/v1/orient`, нажмите **Try it out**, загрузите тестовый PDF-файл и нажмите **Execute**. Нормализованный файл можно будет скачать из блока ответа.

## Результаты тестирования

Я провел тестирование сервиса на всех требуемых краевых сценариях, чтобы убедиться в его отказоустойчивости:

* **Сценарий 1: Корректный документ.** PDF-файл, в котором все страницы изначально имеют правильную ориентацию.
  * *Итог:* Успешно. Алгоритм определяет угол поворота как 0 и оставляет страницы без изменений.
* **Сценарий 2: Документ со смешанной ориентацией.** PDF-файл, страницы которого повернуты вразнобой (на 90, 180 и 270 градусов).
  * *Итог:* Успешно. Каждая страница анализируется независимо, рассчитывается индивидуальный угол, и на выходе все страницы документа приведены к единой ориентации.
* **Сценарий 3: Документы со сложной структурой.** Страницы с малым количеством текста, схемами или корректной альбомной ориентацией.
  * *Итог:* Успешно. За счет внедрения порога уверенности Tesseract (`confidence > 0.5`), алгоритм работает по принципу "не навреди". Если текста недостаточно для точного определения верха и низа, страница пропускается и не искажается.
* **Сценарий 4: Поврежденный или не-PDF файл.** Попытка загрузить переименованный текстовый файл (например, `.txt` с расширением `.pdf`).
  * *Итог:* Успешно. Сервис корректно отлавливает проблему на этапе чтения магических байтов (отсутствие `%PDF-`) и возвращает контролируемую ошибку 400. Процесс приложения при этом не падает.
